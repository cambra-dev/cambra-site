# Cambra

Marketing, blog, and talks site for [cambra.dev](https://cambra.dev) — a new programming system built on a unified model for internet software.

Built with [Astro](https://astro.build), [Tailwind CSS](https://tailwindcss.com), and deployed on [Netlify](https://www.netlify.com).

## Development

Requires Node.js >= 22.12.0.

```sh
npm install
npm run dev
```

The dev server starts at `localhost:4321`.

## Project Structure

```
src/
├── pages/          # Routes (index, blog, talks, thanks)
├── components/     # Astro components (Nav, Hero, Vision, Contact, Team)
├── content/        # Blog posts and talk abstracts (Markdown)
├── decks/          # Slide decks — source + build pipeline, one dir per talk
├── layouts/        # Page layouts
├── data/           # Structured data (team info)
└── styles/         # Global styles
```

Blog posts are authored as Markdown files in `src/content/blog/` and rendered via Astro's content collections.

## Talks

We publish our slides. A talk is two pieces:

| | Where | What it is |
| :-- | :-- | :-- |
| Abstract | `src/content/talks/<slug>.md` | Frontmatter plus prose. Renders on `/talks`. |
| Deck | `src/decks/<deck>/` | Markdown source and the build pipeline that compiles it. |

`/talks` lists every talk with its abstract. `/talks/<slug>/` serves that talk's
deck, and is generated by `src/pages/talks/[slug]/index.astro` from
`src/decks/<deck>/deck.html`.

### Decks are self-contained

A built deck embeds its fonts and logos as `data:` URIs and carries its own
styling and keyboard navigation, so it has **zero external references** and
renders identically offline — which is the property that matters when you're
presenting from someone else's laptop on conference wifi.

That's also why the deck route deliberately doesn't use `BaseLayout`: the global
stylesheet would fight the deck's own. The route contributes only the document
head. Each deck directory has a `README.md` covering its own pipeline; in
general:

```sh
cd src/decks/<deck>
python3 build.py          # deck.md -> deck.html
python3 build.py --check  # per-slide budgets on how much text is on screen
```

Commit `deck.html` — the site build reads it and does not run Python.

### Adding a talk

1. `mkdir src/decks/<deck>` and set up the pipeline (copy an existing deck as a
   starting point), then `python3 build.py`.
2. Write `src/content/talks/<slug>.md` — `title`, `description`, `venue`,
   `pubDate`, and `deck: <deck>` if the directory name differs from the slug.
3. `npm run build`. The route fails loudly if the deck hasn't been built.

### Indexing

Deck pages are **`noindex` by default**, and excluded from the sitemap. A deck is
a few dozen words per slide with its substance in hidden speaker notes, so it
indexes as thin content and competes with the prose that makes the same argument
better. The `/talks` listing carries the abstract, is indexed, and is the page
worth ranking.

Set `indexable: true` in a talk's frontmatter to opt its deck in. As with blog
`draft:`, the sitemap rule is derived from frontmatter in `astro.config.mjs`, so
there's nothing to hand-maintain.

Decks still get full Open Graph and Twitter card metadata regardless — they're
meant to be shared in Slack and DMs, which is unaffected by search indexing.

## Building

```sh
npm run build
```

Output goes to `dist/`.

## Deploying

The site is hosted on Netlify. Build settings are configured in `netlify.toml`.

Pushes to `main` trigger an automatic production deploy via Netlify's GitHub integration. Currently, only commits authored by @sortalongo work because of the Netlify free tier.

**Manual deploy (via CLI):**

```sh
npm run build
npx netlify deploy --prod --dir=dist
```

You'll need to authenticate with `npx netlify login` first.

**DNS:**

The domain `cambra.dev` uses Netlify DNS. Nameservers are configured at the registrar (Namecheap) to point to Netlify's nameservers. SSL is provisioned automatically by Netlify via Let's Encrypt.
